## Tracked G3X Code History: KEYS_MASK0, Power Bit 17, and Playback Bit 16

1. **Pre-PORT-7B Mask (`0x000433F9`)**: Defined in `tests/fixtures/port7b/platform_kbd.h.preimage:7` and `docs/CHDK_G3X_KEYBOARD_MAPPING.md:64`. It covered 11 mapped buttons but omitted both Playback (bit 16, `0x00010000`) and Power (bit 17, `0x00020000`).
2. **PORT-7B Correction (`0x000533F9`)**: In `chdk-port/platform/g3x/platform_kbd.h:4-8` and `docs/PORT7B_PLAYBACK_MASK_CORRECTION.md:5, 48-57`, `KEYS_MASK0` was changed to `0x000533F9`. While `platform_kbd.h` defines the bit masks (and does not define `KEY_PLAYBACK` or `KEY_POWER` symbol names), only bit 16 (`0x00010000`, mapped in `kbd.c:42`) was added to allow ALT mode key suppression in `chdk-port/core/kbd_common.c:179, 324`. Power (bit 17, `0x00020000`) was intentionally kept excluded (`0x000533F9 & 0x00020000 == 0`) so normal camera power-off signals are never masked during shooting.
3. **Runtime Contract Enforcement**: `docs/PORT9B_RUNTIME_CONTRACT.md:36` and `tests/test_port9b_runtime_contract.py:351` pin invariant `C2`: all ALT options must be covered by `KEYS_MASK0`, while Power bit 17 must remain strictly excluded.
4. **PORT-34 Candidate Integration**: In `chdk-port/platform/g3x/sub/110c/kbd_candidate.h:47-48`, constants `G3X_KEY_PLAYBACK_BIT` (`0x00010000`) and `G3X_KEY_POWER_BIT` (`0x00020000`) are explicitly defined. In lines 58-74, `my_kbd_read_keys_candidate()` sets `physw_status[0] |= G3X_KEY_POWER_BIT` (`0x00040DAC`, sourced from `reference/finsig_gm110c/stubs_entry.S:173` and manifest `docs/port34_evidence_manifest.json`) for 100 polling cycles (`G3X_POWERON_HOLD_POLLS = 100`, line 26). Under CHDK's active-low switch convention (`core/kbd_common.c:297, 338`), setting the bit means the button reads as RELEASED, not held, leaving its effect on residency unproven (faking a held press requires clearing the bit with `&= ~0x00020000`), while line 100 sets `conf.alt_mode_button = KEY_PLAYBACK`.

## Recommended Adaptation
- **Closest Sibling**: PowerShot G5 X (GM1.00C), sharing DIGIC 6 architecture, early-boot call tree, and direct GPIO power-cut supervision without relying on the ineffective `0x12345678 @ 0x4ffc` soft-reboot flag.
- **Mechanism 1 (Early-Boot Start Cause)**: In `boot()`, sample GPIO 0x97 (`*(volatile int*)(0xD20B0000 + 0x97*4) & 0x10000`): if 0 (pressed), write `0x80000` (Rec/Power); if non-zero (released), write `0x100000` (Play) to start-cause structure `*(0x9BC4 + 12)` (`0x00009BD0`) (closest sibling `g5x/sub/100c/boot.c:172-182`; GM1.10C `sub_fc08ecbc:177-195`).
- **Mechanism 2 (Early-Boot Power Cut Bypass)**: In caller `sub_fc05b962_my` (`0xFC05B962`), bypass power-cut `sub_fc05ba56` (GPIO 0x67 `0xD20B099C`) and force `r0 = 1` returning from the power-check stage (equivalent to G5X `sub_fc0ecf20_my:411-420`).
- **Mechanism 3 (PhySw Task Replacement)**: Intercept `taskcreate_physw` (`sub_fc1283d2_my` at `0xFC1283D2`) to spawn `mykbd_task` with stack 0x2000 via `j_CreateTaskStrictly` (`0xFC31BE8C`) (`g5x/sub/100c/boot.c:479-506`, `kbd_candidate.h:118-150`).
- **Mechanism 4 (Key State Overrides)**: In `my_kbd_read_keys_candidate` (`kbd_candidate.h:26, 58-74`), the candidate currently sets `physw_status[0] |= 0x20000` (`0x00040DAC`) for 100 polls, which under CHDK active-low convention (`core/kbd_common.c:297, 338`) marks Power RELEASED (effect on residency unproven; INFERRED); to fake a held press, the build task should clear the bit (`physw_status[0] &= ~0x20000`).
