# PORT-48 — DIGIC 6 Large-Block Memory Allocators & Shadow Sizing (GM1.10C)

**Date**: 2026-11-14  
**Scope**: Phase 0 read-only sibling and CHDK core research (`PORT48-ALLOC-RESEARCH`). No code changes.

## 1. Context

In the 2026-11-14 owner hardware trial of the PORT-47 candidate (`docs/PORT47_TRIAL.md:31-35`), the `1,520,640`-byte (`880 x 576 x 3` B) GUI shadow allocation failed (`S:NULL/1520640`): both `malloc(1520640)` and `umalloc(1520640)` returned `NULL` on initial `<ALT>` entry and on `<ALT>` re-entry. A static `.bss` shadow is excluded because growing core `_end` by `1,670,400` B in PORT-43 (`0x003687B0 -> 0x00500FD0`) raised the DryOS system heap base `new_sa = &_end` (`chdk-port/platform/g3x/sub/110c/boot_prototype.c:210-216`) and prevented camera boot (`docs/PORT44_DBUF_HEAP.md:10-23`).

Across the six read-only DIGIC 6 siblings (`g7x`, `g5x`, `sx60hs`, `g16`, `sx280hs`, `sx710hs`), none allocate a 1.5 MB GUI shadow from the DryOS system heap (`CAM_ZEBRA_NOBUF = 1` in each sibling's `platform_camera.h` avoids zebra buffer allocation, and the DryOS system heap `new_sa .. 0x00600014` leaves only `~600 KiB` free after OS/driver init; `chdk-port/platform/sx710hs/notes.txt:18`). For multi-megabyte buffers, CHDK provides `exmem_alloc` (`OPT_EXMEM_MALLOC` + `suba` on pool `0 = EXMEM_RAMDISK`, default `2 MiB`) and `exmem_ualloc` (`exmem_alloc_uncached` in `modules/file_shelter.c`).

### Selection Summary

- **Chosen primary large-block allocator (`chosen=yes`)**: **`exmem_alloc`** (`0xFC092537`, `FINSIG`, `reference/finsig_gm110c/stubs_entry.S:298`, `funcs_by_name.csv:451`) on pool `0` (`EXMEM_RAMDISK`, `stubs_entry.S:132`), used via CHDK's `exmem_alloc_cached(0, size, 0, 0)` (`chdk-port/platform/generic/wrappers.c:1003-1006`) and `suba` (`OPT_EXMEM_MALLOC=1` in `chdk-port/core/memmgmt.c:150-188`, `chdk-port/core/suba.c:243-369`, default `EXMEM_BUFFER_SIZE = 2,097,152` B). Unlike `exmem_ualloc`, `exmem_alloc` returns cached memory suited for CPU-bound shadow fills and `memcpy` row blits (`chdk-port/core/gui_draw.c:204-371`).
- **Chosen free/largest-block query (`chosen=yes (query)`)**: **`GetMemInfo`** (`0xFC610AB9`, `FINSIG`, `reference/finsig_gm110c/stubs_entry.S:235`, `funcs_by_name.csv:755`), wrapped by `GetMemInfo(cam_meminfo*)` in `chdk-port/platform/generic/wrappers.c:1115-1133` (`free_size = fw_info[6]`, `free_block_max_size = fw_info[7]`), complemented by CHDK's `GetExMemInfo(cam_meminfo*)` (`chdk-port/core/memmgmt.c:191-194` -> `suba_getmeminfo` at `chdk-port/core/suba.c:202-240`) when `exmem_heap` is initialized.

## 3. Smaller-Shadow Options Note

- **Drawn ALT/menu rectangle (`width x height` and source)**:
  - **Menu/DBUF shadow rectangle**: **`880 x 576` pixels** (`506,880` pixels) at origin `(G3X_MENU_X0 = 10, G3X_MENU_Y0 = 12)` spanning `x in [10, 889]`, `y in [12, 587]`.
  - **Source of numbers**:
    - Mode 12 LCD visible dimensions are `camera_screen.width = 900`, `camera_screen.height = 600` (`540,000` px) inside a `camera_screen.buffer_width = 928` x `camera_screen.buffer_height = 600` (`556,800` px) hardware overlay buffer (`full_build/g3x/platform_camera.h:76-79`, `full_build/g3x/lib.c:105-122`, `chdk-port/core/gui_draw.c:169,209-211`).
    - Horizontal span: `w = camera_screen.disp_width (900) - 2 * camera_screen.menu_border_width (2 * 10) = 880` px at `x = disp_left (0) + menu_border_width (10) = 10`, with scrollbar width (`wplus = 8`) reserved inside the 880-px box (`chdk-port/platform/g3x/gui_menu.c:280-281,794-801,1438-1453`).
    - Vertical span: With the 2x scaled font (`rbf_font_height() = 32` px, `chdk-port/platform/g3x/gui_menu.c:1555-1558`), `num_lines = (600 - 0) / 32 - 1 = 17` item rows plus `1` header row = `18` rows; `total_h = 18 * 32 = 576` px centered at `header_y = ((600 - 16 * 32) >> 1) - 32 = 12` (`chdk-port/platform/g3x/gui_menu.c:279,791,824,1436-1447`; `chdk-port/core/gui_draw.c:69-75,97-108`; `chdk-port/platform/g3x/gui_diag.h:24-39`).
    - Note on `<ALT>` status lines: In `<ALT>` mode, the helper block (`560` px wide at `x = 170, y >= 32`, `chdk-port/core/gui.c:2589-2600`), the PORT-46 `kbd_check` line (`736 x 32` at `x = 82, y = 504..535`, `chdk-port/platform/g3x/kbd_check.h:46-48`), and the PORT-47 `gui_diag` line (`816 x 32` at `x = 42, y = 536..567`, `chdk-port/platform/g3x/gui_diag.h:244-246`) all lie inside `880 x 576`; only the bottom `<ALT>` title bar at `y = 600 - 32 = 568..599` (`chdk-port/core/gui.c:2692-2699`) extends 12 rows below `y = 587` (extending the box to `y = 12..599` would make it `880 x 588` = `517,440` pixels).
- **Byte size at full depth (`3 bytes/pixel`: 2 B/px 16-bpp UYVY bitmap + 1 B/px 8-bpp opacity)**:
  - **`880 x 576` drawn rectangle**: `880 * 576 * 2 = 1,013,760` B bitmap (`G3X_SHADOW_BM_SIZE`) + `880 * 576 * 1 = 506,880` B opacity (`G3X_SHADOW_OP_SIZE`) = **`1,520,640` bytes** (`0x173400`, `~1.45 MiB`, `G3X_SHADOW_TOTAL_SIZE` in `chdk-port/core/gui_draw.c:106-108`, `chdk-port/platform/g3x/gui_diag.h:36-38`).
  - *(For comparison, the full `928 x 600` buffer in PORT-43 was `1,113,600 + 556,800 = 1,670,400` bytes; `880 x 588` including the bottom 12 `<ALT>` rows is `1,034,880 + 517,440 = 1,552,320` bytes.)*
- **Byte size at 1 byte per pixel (CHDK `color` palette index only, expanded on blit)**:
  - **`880 x 576` drawn rectangle**: `880 * 576 * 1 =` **`506,880` bytes** (`0x7BC00`, `~495.0 KiB`) — a **3x reduction** (`-1,013,760` B) compared to the full-depth shadow.
  - *(For comparison, `880 x 588` at 1 B/px is `517,440` bytes; the full `928 x 600` buffer at 1 B/px is `556,800` bytes.)*
  - Because every CHDK primitive in `chdk-port/core/gui_draw.c:13-35,204-334,387-457,490-497` derives `(u, y, v, opacity)` deterministically from a 1-byte `color` index (`CALC_YUV_LUMA_OPACITY_FOR_COLOR` and `CALC_YUV_CHROMA_FOR_COLOR`), storing 1 byte/pixel in the shadow and expanding horizontal pixel pairs `(c0, c1)` via a 256-entry LUT during `g3x_dbuf_shadow_restore()` (`chdk-port/core/gui_draw.c:341-371`) into 32-bit UYVY words (`bitmap_buffer[0..1]`) and 16-bit opacity halfwords (`opacity_buffer[0..1]`) preserves identical visual output at one-third the memory footprint.
