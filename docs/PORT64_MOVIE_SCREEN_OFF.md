## 4. `PORT64-IMPLEMENT`: Bounded Screen-Off & Restoration Policy (`TurnOffBackLight` / `TurnOnBackLight`)

- **Firmware entry points & task context (`FINSIG` + `ROM_VERIFIED` via `PORT64-ROM-BACKLIGHT-CORE-WINDOW` & `PORT64-ROM-DISPCON-BACKLIGHT-WINDOW`)**:
  - `TurnOffBackLight` (`0xFC37C449`, `_TurnOffBackLight`): `void TurnOffBackLight(void)` (`0` args); locks DispCon semaphore `[r4, #0x4C]` (`timeout = 10000`), idempotent on `[r4, #0x10] == 1`, turns off LCD backlight hardware, writes `[r4, #0x10] = 0` while leaving `[r4, #0x14] == 1` intact, and releases `[r4, #0x4C]`.

- **Bounded screen-off activation, refresh, manual toggle & restoration rules**:
  1. **Armed-recording & post-start settle precondition (`G3X_AUTOCONT_SCREEN_OFF_DELAY_POLLS = 100U`, `1.0 s`)**: `TurnOffBackLight()` is never called while `G3X_AUTOCONT_DISARMED` (idle, playback, or unattributed recording) or while physical `KEY_VIDEO` is still held from start.   2. **Bounded periodic refresh (`G3X_AUTOCONT_SCREEN_REFRESH_POLLS = 3000U`, `30.0 s`; cap `G3X_AUTOCONT_SCREEN_MAX_REFRESH_CALLS = 120U` per clip)**: Because runtime Canon wake behavior during recording is explicitly **`UNVERIFIED` / `UNKNOWN`**, while `g3x_autocont_screen_off_active == 1` in `G3X_AUTOCONT_RECORDING`, the controller calls idempotent `TurnOffBackLight()` at most once every `3000` polls (`30.0 s`), capped at `120` periodic refreshes (`60 min`) per clip.
