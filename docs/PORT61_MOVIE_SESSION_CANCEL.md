## 2. Detailed Cancellation Analysis: Active-Clip Preservation, Budget Invariance, Ordering, Precedence, Idempotence & Clearing Rules

### 2.1 Active-Clip, Allowance, Consumed-Budget & Continuation-Owned Key Behavior on Cancellation

1. **Preserving an Active Recording Clip (`mr_rec_state == 1`)**:
   - In `chdk-port/platform/g3x/sub/110c/movie_rec.c`, the continuation controller never writes to `mr_rec_state` (`0x0000C0C8`, strictly read-only in `g3x_get_movie_status()` at `movie_rec.c:22-33`) and never emits a synthetic `KEY_VIDEO` pulse on disarm or user disable (`g3x_autocont_disarm_with_reason()` at `movie_rec.c:320-341` and `g3x_movie_autocont_set_enabled(0)` at `movie_rec.c:510-529`).
   - Meanwhile, `g3x_movie_nolimit_poll()` (`movie_rec.c:104-130`, called independently in `full_build/g3x/kbd.c:124-127` before `g3x_movie_autocont_poll()`) depends only on `g3x_get_movie_status() == 1` and continues patching `mr_max_frames` (`0x0000C274`) to `0xFFFFFFFFU` (`LIM:OFF`) regardless of `g3x_autocont_state`.
   - Therefore, cancelling session continuation while `mr_rec_state == 1` (`G3X_AUTOCONT_RECORDING`, or if `mr_rec_state` becomes `1` during `PRESSING`/`RELEASING`/`WAIT_CONFIRM`) leaves the active recording clip running uninterrupted with `LIM:OFF` active.
2. **Preserving Configured Allowance (`g3x_autocont_restart_budget`), Remaining Allowance (`g3x_autocont_restarts_remaining`) & Consumed Budget (`g3x_autocont_session_restarts_used`)**:
   - In `movie_rec.c:320-341` (`g3x_autocont_disarm_with_reason()`) and `movie_rec.c:510-529` (`g3x_movie_autocont_set_enabled(0)`), disarming clears `g3x_autocont_attempt_admitted = 0` (`movie_rec.c:328,524`) and resets per-clip metrics (`g3x_autocont_reset_session_metrics()`, `movie_rec.c:310-318`), while leaving `g3x_autocont_restart_budget` (`1..3`), `g3x_autocont_restarts_remaining`, and `g3x_autocont_session_restarts_used` completely untouched (never refunding an already-admitted attempt and never mutating the configured allowance or consumed count).
   - If session cancellation is invoked during `G3X_AUTOCONT_RECORDING` **before** stop-onset restart admission (`movie_rec.c:1006-1017`), no restart attempt has been admitted for the current clip yet, so `g3x_autocont_restarts_remaining` and `g3x_autocont_session_restarts_used` remain at their current session values (`restarts_remaining == B - used`, `session_restarts_used == used`), and cancelling the session prevents the upcoming clip stop from being admitted or consuming another unit of allowance.
   - If session cancellation is invoked during a pending continuation phase (`WAIT_IDLE`, `SETTLE`, `PRESSING`, `RELEASING`, `WAIT_CONFIRM`) **after** stop-onset admission (`movie_rec.c:1014-1016`) has already reserved 1 allowance for that attempt, cancellation aborts the pending continuation and clears `g3x_autocont_attempt_admitted = 0` without refunding `g3x_autocont_restarts_remaining` or decrementing `g3x_autocont_session_restarts_used`.
3. **Cancelling Pending Continuation & Releasing Only Continuation-Owned Synthetic Keys**:
   - Calling `g3x_autocont_release_synth_input()` (`movie_rec.c:297-308`) inside the cancellation/disarm path checks `if (g3x_autocont_synth_owned)`:
     - When `g3x_autocont_synth_owned == 1` (active only during `G3X_AUTOCONT_PRESSING`, `movie_rec.c:290-295,1102,1133`), it calls `kbd_key_release(KEY_VIDEO)`, restores bit 3 (`0x00000008`) in `physw_status[0]` iff physical `KEY_VIDEO` is not held (`(kbd_new_state[0] & G3X_KEY_VIDEO_BIT) != 0U`), and zeroes `g3x_autocont_synth_owned = 0`.
     - When `g3x_autocont_synth_owned == 0` (`RECORDING`, `WAIT_IDLE`, `SETTLE`, `RELEASING`, `WAIT_CONFIRM`, or `DISARMED`), `g3x_autocont_release_synth_input()` performs zero calls to `kbd_key_release()` and leaves all unowned `kbd_mod_state[0]` and `physw_status[0]` bits untouched.

### 2.2 Cancellation vs. Admission Ordering, Physical-Stop Precedence, Idempotence, Idle No-Op & Deliberate Physical-Start Clearing

1. **Cancellation vs. Restart Admission Ordering**:
   - On hardware, menu callbacks run inside `mykbd_task()` during `kbd_update_key_state()` (`full_build/g3x/kbd.c:118` -> `chdk-port/core/kbd_common.c:166` -> `chdk-port/core/kbd_process.c:193` -> `chdk-port/core/gui.c:3081` -> `chdk-port/platform/g3x/gui_menu.c:652-800`), which executes **before** `g3x_movie_autocont_poll()` (`full_build/g3x/kbd.c:130`) on the same `10 ms` tick.
   - Furthermore, within `g3x_movie_autocont_poll()` (`chdk-port/platform/g3x/sub/110c/movie_rec.c:800-1234`), any active-session cancellation request (whether applied immediately by the cancel entry point or checked at the top of `G3X_AUTOCONT_RECORDING` / pending states) is evaluated **before** the stop-onset eligibility and budget admission block (`movie_rec.c:995-1028`, where `cur_state != G3X_MOVIE_STATE_RECORDING` calls `g3x_autocont_check_eligible_stop()` and decrements `g3x_autocont_restarts_remaining--`).
   - Consequently:
     - If cancellation occurs before or on the same poll as a clip's `RECORDING (1) -> STOPPING (2..4) / IDLE (0)` transition, cancellation transitions the controller out of `G3X_AUTOCONT_RECORDING` to `G3X_AUTOCONT_DISARMED` **before** restart admission runs: the stop is never admitted, `g3x_autocont_restarts_remaining` is not decremented for that stop, `g3x_autocont_session_restarts_used` is not incremented, and `WAIT_IDLE`/`SETTLE`/`PRESSING` are never entered.
     - If cancellation occurs while a restart attempt is already pending in `WAIT_IDLE`, `SETTLE`, `PRESSING`, `RELEASING`, or `WAIT_CONFIRM`, cancellation executes before the state can advance to `PRESSING` or `g3x_autocont_enter_confirmed_recording()`, immediately releasing any continuation-owned synthetic key, clearing `g3x_autocont_attempt_admitted = 0`, and returning to `G3X_AUTOCONT_DISARMED`.
2. **Physical-Stop Precedence (`G3X_AUTOCONT_REASON_PHYS_STOP`)**:
   - In `g3x_movie_autocont_poll()`, raw physical `KEY_VIDEO` (`phys_video_pressed = (((unsigned int)kbd_new_state[0] & G3X_KEY_VIDEO_BIT) == 0U)`, `movie_rec.c:804`) is checked first in `in_playback || invalid_rec_state` (`movie_rec.c:820-833`), at the top of `G3X_AUTOCONT_RECORDING` (`movie_rec.c:974-989`, once initial start-hold carry-over releases or `cur_state != 1`), and at the top of every pending state (`WAIT_IDLE` at `movie_rec.c:1034-1038`, `SETTLE` at `1073-1077`, `PRESSING` at `1109-1113`, `RELEASING` at `1146-1150`, and `WAIT_CONFIRM` at `1188-1192`).
   - Even after a GUI session cancellation has disarmed the controller to `G3X_AUTOCONT_DISARMED` while the active clip continues recording (`cur_state == 1`) or is stopping (`cur_state in 2..4`), pressing the physical `KEY_VIDEO` button hits the `G3X_AUTOCONT_DISARMED` non-idle branches (`movie_rec.c:947-951,958-962`), which latch `g3x_autocont_cancel_latched = 1` and set `g3x_autocont_disarm_reason = G3X_AUTOCONT_REASON_PHYS_STOP` (`"STOP"`). And if physical `KEY_VIDEO` is pressed on the same poll as a GUI session-cancel request (or while physical `KEY_VIDEO` is held outside the initial start-hold window), physical-stop precedence (`G3X_AUTOCONT_REASON_PHYS_STOP`, `g3x_autocont_cancel_latched = 1`) takes priority over GUI session cancellation.
3. **Idempotence & Idle No-Op Behavior**:
   - **Idle / disarmed no-op**: When no active or pending continuation session exists (`g3x_autocont_state == G3X_AUTOCONT_DISARMED`, whether at boot `AC:OFF`, armed-ready at idle `AC:RDY`, faulted `AC:FLT`, or already session-cancelled while the current clip finishes or sits at idle), invoking the session-cancel action must be a strict no-op (returning `0` / current status string without mutating `g3x_autocont_enabled`, `g3x_autocont_restart_budget`, `g3x_autocont_restarts_remaining`, `g3x_autocont_session_restarts_used`, `g3x_autocont_disarm_reason`, `g3x_autocont_cancel_latched`, `g3x_autocont_idle_start_press_seen`, or synthetic key state).
   - **Active-session idempotence**: Once an active or pending session (`g3x_autocont_state in {RECORDING, WAIT_IDLE, SETTLE, PRESSING, RELEASING, WAIT_CONFIRM}`) is cancelled via the GUI session-cancel action, it transitions immediately to `G3X_AUTOCONT_DISARMED` (with session-cancel state latched and `g3x_autocont_enabled` preserved at `1`). Any subsequent repeated session-cancel invocations during the remainder of that active clip, during its stop transition, or at idle find `g3x_autocont_state == G3X_AUTOCONT_DISARMED` (already cancelled) and execute as idempotent no-ops with zero additional state mutations or key release calls.
4. **Clearing Only on a Deliberate Physical Start After Confirmed Idle**:
   - Unlike `g3x_autocont_cancel_latched` (the hardware button-release debounce latch for physical `KEY_VIDEO`, which clears automatically as soon as `cur_state == G3X_MOVIE_STATE_IDLE && !phys_video_pressed` at `movie_rec.c:869-872,896-899`), the GUI session-cancellation state must **not** clear merely when the active clip stops or reaches `G3X_MOVIE_STATE_IDLE (0)`, nor on any synthetic/unattributed `0 -> 1` transition.
   - Instead, after GUI session cancellation:
     1. While the current clip continues recording (`cur_state == 1`) and while it stops (`cur_state in 2..4 -> 0`), `g3x_autocont_state` remains `G3X_AUTOCONT_DISARMED` (`g3x_autocont_enabled == 1`), so no automatic continuation can trigger when the clip reaches Reason 3 or Reason 4.
     2. Once the camera returns to confirmed `G3X_MOVIE_STATE_IDLE (0)` (`g3x_autocont_saw_boot_idle == 1`, `cur_state == 0`, `!g3x_autocont_cancel_latched`), `G3X_AUTOCONT_DISARMED` remains armed for a new physical press (`movie_rec.c:883-893`: observing `phys_video_pressed` at confirmed `IDLE` sets `g3x_autocont_idle_start_press_seen = 1` and `g3x_autocont_idle_press_age = 200`).
     3. The session-cancellation state clears **only** when that subsequent deliberate physical start transitions `prev_state == G3X_MOVIE_STATE_IDLE (0) -> cur_state == G3X_MOVIE_STATE_RECORDING (1)` at `movie_rec.c:924-942` (which arms the new session to `G3X_AUTOCONT_RECORDING`, clears `g3x_autocont_disarm_reason = G3X_AUTOCONT_REASON_NONE`, and initializes fresh session budget `g3x_autocont_restarts_remaining = g3x_autocont_restart_budget` and `g3x_autocont_session_restarts_used = 0U`)—or when explicitly reset/overwritten by physical stop (`G3X_AUTOCONT_REASON_PHYS_STOP`), user disable (`set_enabled(0)`), confirmed-idle re-enable/budget edit, fault (`PLAYBACK` / `INVALID_STATE`), or reboot (`g3x_movie_autocont_reset()`).

     - Prevents any restart admission at stop-onset (`1 -> != 1`) or continuation progression for the cancelled session while leaving an active clip (`mr_rec_state == 1`) recording uninterrupted,

### 4.2 How Existing Cancellation & Interfaces Can Be Reused Directly

1. **Reuse `g3x_autocont_disarm_with_reason(0, reason, 0)` (`chdk-port/platform/g3x/sub/110c/movie_rec.c:320-341`)**:
   - Calling `g3x_autocont_disarm_with_reason(/*latch_cancel=*/0, /*reason=*/..., /*disable_toggle=*/0)` already performs the exact low-level teardown needed for session cancellation:
     1. Calls `g3x_autocont_release_synth_input()` (`movie_rec.c:322`), which releases `KEY_VIDEO` in `kbd_mod_state[0]` and `physw_status[0]` **only** if `g3x_autocont_synth_owned != 0` (`movie_rec.c:297-308`),
     2. Calls `g3x_autocont_reset_session_metrics()` (`movie_rec.c:323`), resetting only per-clip metrics (`saw_frames_in_bounds`, `saw_size_in_bounds`, `held_from_idle`, `start_hold_polls`, `session_prev_*`) while preserving `g3x_autocont_restart_budget`, `g3x_autocont_restarts_remaining`, and `g3x_autocont_session_restarts_used`,
     3. Clears `g3x_autocont_idle_start_press_seen = 0`, `g3x_autocont_idle_press_age = 0U`, `g3x_autocont_timer_polls = 0U`, and `g3x_autocont_attempt_admitted = 0` (`movie_rec.c:324-329`), and
     4. Sets `g3x_autocont_state = G3X_AUTOCONT_DISARMED` while keeping `g3x_autocont_enabled = 1` (`disable_toggle == 0`).
2. **Reuse `G3X_AUTOCONT_DISARMED` Confirmed-Idle & Deliberate Physical-Start Arming (`chdk-port/platform/g3x/sub/110c/movie_rec.c:880-965`)**:
   - Because `g3x_autocont_disarm_with_reason(0, ..., 0)` transitions `g3x_autocont_state` to `G3X_AUTOCONT_DISARMED` with `g3x_autocont_enabled == 1` and `g3x_autocont_idle_start_press_seen == 0`:
     - While the active clip continues recording (`cur_state == 1`, `movie_rec.c:917-953`), `g3x_autocont_idle_start_press_seen` is `0`, so the `else` branch (`movie_rec.c:943-952`) keeps the controller in `G3X_AUTOCONT_DISARMED` (and if physical `KEY_VIDEO` is pressed during `cur_state == 1` or `cur_state in 2..4`, `movie_rec.c:947-951,958-962` automatically latches `g3x_autocont_cancel_latched = 1` and `g3x_autocont_disarm_reason = G3X_AUTOCONT_REASON_PHYS_STOP`, preserving physical-stop precedence!).
     - When the active clip later hits Reason 3 or Reason 4 (`cur_state: 1 -> 2 -> 0`), the controller is already in `G3X_AUTOCONT_DISARMED`, so `case G3X_AUTOCONT_RECORDING:` (`movie_rec.c:995-1028`) is never entered, zero restart admission occurs, and zero budget allowance is consumed.
     - Once the camera reaches confirmed `IDLE (0)` (`cur_state == 0`, `movie_rec.c:883-916`), `G3X_AUTOCONT_DISARMED` waits for a new physical `KEY_VIDEO` press (`phys_video_pressed && !g3x_autocont_cancel_latched` -> `g3x_autocont_idle_start_press_seen = 1`), and only on the subsequent `prev_state == 0 && cur_state == 1` transition (`movie_rec.c:924-942`) does it clear the session-cancel state, arm `G3X_AUTOCONT_RECORDING`, and initialize `g3x_autocont_restarts_remaining = g3x_autocont_restart_budget` and `g3x_autocont_session_restarts_used = 0U`.
3. **Reuse `g3x_movie_autocont_can_enable()` (`chdk-port/platform/g3x/sub/110c/movie_rec.c:481-506`)**:
   - Even after a session is cancelled while the active clip is still recording (`g3x_autocont_state == G3X_AUTOCONT_DISARMED`, `cur_state == 1`) or stopping (`cur_state in 2..4`), or on the first poll after returning to `IDLE` (`prev_rec_state != 0`), `g3x_movie_autocont_can_enable()` returns `0` because `cur_state != 0 || g3x_autocont_prev_rec_state != 0` (`movie_rec.c:493-496`). Thus budget edits (`g3x_movie_autocont_set_restart_budget()`) remain strictly blocked until the clip finishes and two consecutive `IDLE (0)` polls confirm idle.
