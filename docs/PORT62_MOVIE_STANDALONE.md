   - Because `G3X_MOVIE_STANDALONE=1` has no CHDK GUI menu to invoke `g3x_movie_autocont_set_enabled(1)`, `g3x_autocont_enabled` initializes to `1` at boot (`movie_rec.c:243`) and resets to `1` in `g3x_movie_autocont_reset()` (`movie_rec.c:473`) when `G3X_MOVIE_STANDALONE == 1` (while remaining `0` at boot/reset for all non-standalone profiles `PORT-57..61`).

   - **Stage 1 (Confirmed boot idle)**: `g3x_movie_autocont_poll()` refuses to arm or latch any start press until it observes `cur_state == G3X_MOVIE_STATE_IDLE (0)` in record mode (`camera_info.state.mode_play == 0`), which sets `g3x_autocont_saw_boot_idle = 1` (`movie_rec.c:1100`). If booted while `mr_rec_state != 0` or in playback mode, no session can arm.
   - **Stage 2 (Deliberate physical start recognition)**: Being enabled at boot (`g3x_autocont_enabled == 1` in `G3X_AUTOCONT_DISARMED`) never issues synthetic input at boot. Entering `G3X_AUTOCONT_RECORDING (1)` requires:
     1. Observing a raw physical `KEY_VIDEO` press (`phys_video_pressed = (((unsigned int)kbd_new_state[0] & G3X_KEY_VIDEO_BIT) == 0U)`) while in `G3X_AUTOCONT_DISARMED (0)` at confirmed `IDLE` (`cur_state == G3X_MOVIE_STATE_IDLE (0)`, `prev_state == G3X_MOVIE_STATE_IDLE (0)` when recovering from cancellation/disarm, and `!g3x_autocont_cancel_latched`), which latches `g3x_autocont_idle_start_press_seen = 1` and `g3x_autocont_idle_press_age = G3X_AUTOCONT_CONFIRM_POLLS` (`200` polls = `2.0 s`, `movie_rec.c:1101-1140`), and
     2. Observing `prev_state == G3X_MOVIE_STATE_IDLE (0) && cur_state == G3X_MOVIE_STATE_RECORDING (1)` before `g3x_autocont_idle_press_age` expires (`movie_rec.c:1149-1170`).
   - Any unattributed `0 -> 1` transition without `g3x_autocont_idle_start_press_seen == 1` (or after `idle_press_age` expires after `200` polls) leaves the controller in `G3X_AUTOCONT_DISARMED (0)` (`movie_rec.c:1171-1198`).
2. **Inherited `PORT-60` Finite-Budget Semantics**:
   - **Default budget**: `g3x_autocont_restart_budget` defaults to `G3X_AUTOCONT_BUDGET_DEFAULT = 1U` (`1` automatic restart per physical session = up to `2` clips total per deliberate physical start; host tests may also exercise allowances `1U`, `2U`, `3U` via `g3x_movie_autocont_set_restart_budget()` at confirmed idle).
   - **Initialization on deliberate physical start only**: When a deliberate physical start transitions `G3X_AUTOCONT_DISARMED (0) -> G3X_AUTOCONT_RECORDING (1)` (`movie_rec.c:1149-1170`), the controller initializes `g3x_autocont_restarts_remaining = g3x_autocont_restart_budget`, `g3x_autocont_session_restarts_used = 0U`, `g3x_autocont_attempt_admitted = 0`, and `g3x_autocont_session_cancelled = 0`.
   - **Atomic pre-input reservation**: At stop onset in `G3X_AUTOCONT_RECORDING` (`cur_state != 1` at `movie_rec.c:1256-1289`), after `g3x_autocont_check_eligible_stop(&attributed_reason) == 1`:
     - If `g3x_autocont_restarts_remaining == 0U || g3x_autocont_session_restarts_used >= g3x_autocont_restart_budget || g3x_autocont_attempt_admitted != 0`, continuation disarms immediately (`g3x_autocont_disarm_with_reason(0, G3X_AUTOCONT_REASON_NONE, 0)`) without entering `WAIT_IDLE`, `SETTLE`, or `PRESSING`.
     - Otherwise, 1 allowance is reserved atomically (`g3x_autocont_restarts_remaining--`, `g3x_autocont_session_restarts_used++`, `g3x_autocont_attempt_admitted = 1`) **before** entering `WAIT_IDLE` or `SETTLE` and **before** any synthetic `KEY_VIDEO` input is emitted in `PRESSING`.
   - **Pending-state budget verification & no-refund rule**: Every pending and outstanding state (`WAIT_IDLE`, `SETTLE`, `PRESSING`, `RELEASING`, `WAIT_CONFIRM` at `movie_rec.c:1312,1358,1402,1447,1498`) verifies `g3x_autocont_attempt_admitted == 1 && 0U < g3x_autocont_session_restarts_used <= g3x_autocont_restart_budget` on every poll. Any failed, timed-out, or interrupted attempt clears `g3x_autocont_attempt_admitted = 0` on disarm and **never refunds** `g3x_autocont_restarts_remaining` or decrements `g3x_autocont_session_restarts_used`.
   - **Synthetic-start non-reset**: When an admitted synthetic restart confirms recording (`cur_state == 1` at `movie_rec.c:1468-1471,1506-1510`), `g3x_autocont_enter_confirmed_recording()` (`movie_rec.c:447-467`) resets per-clip metrics (`g3x_autocont_reset_session_metrics()`), clears `g3x_autocont_attempt_admitted = 0`, increments `g3x_autocont_restart_count++`, and re-enters `G3X_AUTOCONT_RECORDING (1)` while **preserving** `g3x_autocont_restarts_remaining` and `g3x_autocont_session_restarts_used`. When the final (`B`-th) continued clip later stops, `g3x_autocont_restarts_remaining == 0U` disarms immediately at stop onset without entering `WAIT_IDLE` or `SETTLE`.
3. **Fail-Closed Continuation Restricted to Confirmed Natural Stops with Reason 3 or 4 and All Existing Admission Predicates**:
   - **Active recording duration patch (`PORT-56`)**: On every `10 ms` tick while `g3x_get_movie_status() == 1`, `g3x_movie_nolimit_poll()` (`movie_rec.c:104-115`) checks `*(volatile unsigned int *)0x0000C274` (`mr_max_frames`) and overwrites it with `0xFFFFFFFFU` whenever `val != 0U && val != 0xFFFFFFFFU`, defeating the 29:59 (`1799` s) / 59:59 (`3599` s) frame limit on the initial clip and on every auto-continued clip after `MovieRecorder_SetupModeAndLimits` (`0xFC097D72` @ `0xFC09A97C`) runs.
   - **Per-clip counter movement & in-bounds progression (`g3x_autocont_sample_recording_metrics()`, `movie_rec.c:362-406`)**:
     - Stop-time counters (`cur_frames`, `stream_bytes`, `proj_total`) are snapshotted into `g3x_autocont_last_stop_*` on every stop (`movie_rec.c:355-360,882,1233,1245,1260`).
     - In the next clip, `g3x_autocont_saw_frames_in_bounds` (`0U < cur_frames < max_frames < 0xFFFFFFFFU`) and `g3x_autocont_saw_size_in_bounds` (`cur_frames > 0U && stream_bytes > 0ULL && size_cap > 0ULL && 0ULL < proj_total <= size_cap && avail_space >= proj_total`) can latch to `1` **only after** the corresponding counters move/reset from `g3x_autocont_last_stop_*` (and reset to `0` if `cur_frames` or `stream_bytes` decreases when `SetupModeAndLimits` completes after `mr_rec_state` reaches `1`).
   - **Stop-onset admission (`g3x_autocont_check_eligible_stop()`, `movie_rec.c:408-445`)**:
     - Admits **Reason 3 (4 GiB size policy cap)** iff `g3x_get_movie_stop_reason() == 3U && g3x_autocont_saw_size_in_bounds == 1 && size_cap > 0ULL && avail_space >= proj_total && proj_total > size_cap`.
     - Admits **Reason 4 (duration/frame limit cap)** iff `g3x_get_movie_stop_reason() == 4U && g3x_autocont_saw_frames_in_bounds == 1 && 0U < max_frames < 0xFFFFFFFFU && cur_frames >= max_frames`.
     - Any other stop reason (`0` user, `1` buffer overflow, `2` card full, `>= 5` unknown/thermal/battery), stale `3` or `4` without matching per-clip in-bounds progression and threshold failure, or invalid `mr_rec_state` (`< 0` or `> 4`) fails closed immediately (`G3X_AUTOCONT_REASON_STOP_FAULT` / `G3X_AUTOCONT_REASON_INVALID_STATE`) before budget reservation and without issuing any synthetic key press.
   - **Bounded single-shot synthetic restart sequence**:
     - `G3X_AUTOCONT_WAIT_IDLE (2)`: waits up to `G3X_AUTOCONT_MAX_STOP_POLLS = 500U` (`5.0 s`) for `cur_state in 2..4` to reach `0` (`IDLE`); disarms with `G3X_AUTOCONT_REASON_TIMEOUT` on expiry or `G3X_AUTOCONT_REASON_INVALID_STATE` if `cur_state == 1`.
     - `G3X_AUTOCONT_SETTLE (3)`: requires `G3X_AUTOCONT_SETTLE_POLLS = 50U` (`500 ms`) of continuous `cur_state == 0` before pressing `KEY_VIDEO`; disarms with `G3X_AUTOCONT_REASON_INVALID_STATE` if `cur_state != 0`.
     - `G3X_AUTOCONT_PRESSING (4)`: asserts owned synthetic `KEY_VIDEO` press for `G3X_AUTOCONT_PRESS_POLLS = 6U` (`60 ms`), then releases owned synthetic input and enters `G3X_AUTOCONT_RELEASING (5)`.
     - `G3X_AUTOCONT_RELEASING (5)`: holds `KEY_VIDEO` released for `G3X_AUTOCONT_RELEASE_POLLS = 6U` (`60 ms`); if `cur_state == 1` on completion, calls `g3x_autocont_enter_confirmed_recording()`, else enters `G3X_AUTOCONT_WAIT_CONFIRM (6)`.
     - `G3X_AUTOCONT_WAIT_CONFIRM (6)`: waits up to `G3X_AUTOCONT_CONFIRM_POLLS = 200U` (`2.0 s`) for `cur_state == 1` with zero additional key pulses; disarms with `G3X_AUTOCONT_REASON_TIMEOUT` on expiry without retry.

## 6. Physical-Button Precedence, Continuation-Owned Key Release, Synthetic-Event Exclusion & Session Cancellation / Rearming

1. **Synthetic-Event Exclusion from Physical Input Attribution**:
   - On each `10 ms` tick of `mykbd_task()`, `kbd_fetch_data(kbd_new_state)` (`full_build/g3x/kbd.c:145-149`) writes the raw hardware key state into `kbd_new_state[0..2]` before any modifier or `physw_status` override.
   - `g3x_autocont_assert_synth_press()` (`chdk-port/platform/g3x/sub/110c/movie_rec.c:293-298`) writes **only** `kbd_mod_state[0]` (via `kbd_key_press(KEY_VIDEO)`) and `physw_status[0]` (`0x00040DAC`); it never modifies `kbd_new_state[0]`.
   - `phys_video_pressed` (`((unsigned int)kbd_new_state[0] & G3X_KEY_VIDEO_BIT) == 0U`, `movie_rec.c:955`) reads exclusively `kbd_new_state[0]`.
   - Consequently, continuation-owned synthetic `KEY_VIDEO` presses are **100% excluded** from `phys_video_pressed`: a synthetic pulse can never self-trigger a physical-stop veto during `PRESSING`, and can never set `g3x_autocont_idle_start_press_seen` (`movie_rec.c:1101-1118`) to forge a physical session start or clear session cancellation.
2. **Physical-Button Precedence During Active Recording, Pending Restarts (`WAIT_IDLE`, `SETTLE`) & Outstanding Restarts (`PRESSING`, `RELEASING`, `WAIT_CONFIRM`)**:
   - **Active recording (`G3X_AUTOCONT_RECORDING`, `movie_rec.c:1218-1239`)**:
     - Carry-over of the initial physical start press from `IDLE` is bounded by `g3x_autocont_held_from_idle == 1 && cur_state == 1 && g3x_autocont_start_hold_polls > 0U` (`G3X_AUTOCONT_START_HOLD_POLLS = 50U` / `500 ms`).
     - Once the initial press is released (`!phys_video_pressed`), or `start_hold_polls` reaches `0U`, or `cur_state != 1` (same-poll race between a physical `KEY_VIDEO` press and a Reason 3/4 stop transition), `phys_video_pressed` is evaluated **first**—before session cancellation (`movie_rec.c:1240`) and before stop eligibility/budget admission (`movie_rec.c:1256-1278`). It snapshots stop counters if `cur_state != 1` and immediately disarms with `g3x_autocont_disarm_with_reason(1, G3X_AUTOCONT_REASON_PHYS_STOP, 0)`.
   - **Pending continuation (`G3X_AUTOCONT_WAIT_IDLE` at `movie_rec.c:1295-1299`, `G3X_AUTOCONT_SETTLE` at `1345-1349`) & outstanding restart attempts (`G3X_AUTOCONT_PRESSING` at `1388-1392`, `G3X_AUTOCONT_RELEASING` at `1433-1437`, `G3X_AUTOCONT_WAIT_CONFIRM` at `1483-1487`)**:
     - In every pending and outstanding state (as well as same-poll playback or invalid-state races at `movie_rec.c:972-1006`), `if (phys_video_pressed)` is checked **first** on every `10 ms` tick.
     - Pressing physical `KEY_VIDEO` during any pending or outstanding restart immediately aborts the restart, calls `g3x_autocont_release_synth_input()`, clears `g3x_autocont_attempt_admitted = 0` without refunding the consumed budget unit, latches `g3x_autocont_cancel_latched = 1` with `G3X_AUTOCONT_REASON_PHYS_STOP`, and transitions to `G3X_AUTOCONT_DISARMED (0)`.
3. **Continuation-Owned Key Release (`g3x_autocont_synth_owned`)**:
   - `g3x_autocont_assert_synth_press()` (`movie_rec.c:293-298`, called only in `G3X_AUTOCONT_PRESSING` at `movie_rec.c:1381,1420`) sets `g3x_autocont_synth_owned = 1`, calls `kbd_key_press(KEY_VIDEO)` (`kbd_mod_state[0] &= ~0x00000008L`), and clears bit 3 in `physw_status[0]` (`physw_status[0] &= ~0x00000008L`).
   - `g3x_autocont_release_synth_input()` (`movie_rec.c:300-311`) executes **only** when `g3x_autocont_synth_owned != 0`:
     - Calls `kbd_key_release(KEY_VIDEO)` (`kbd_mod_state[0] |= 0x00000008L`),
     - Restores bit 3 in `physw_status[0]` (`physw_status[0] |= 0x00000008L`) iff physical `KEY_VIDEO` is not held (`((unsigned int)kbd_new_state[0] & G3X_KEY_VIDEO_BIT) != 0U`), and
     - Clears `g3x_autocont_synth_owned = 0`.
   - When `g3x_autocont_synth_owned == 0` (in `DISARMED`, `RECORDING`, `WAIT_IDLE`, `SETTLE`, `RELEASING`, and `WAIT_CONFIRM`), `g3x_autocont_release_synth_input()` performs zero calls to `kbd_key_release()` and leaves all unowned `KEY_VIDEO` and non-`KEY_VIDEO` bits in `kbd_mod_state[0..2]` and `physw_status[0..2]` untouched.
4. **Session Cancellation & Rearming Contract in `G3X_MOVIE_STANDALONE=1`**:
   - **Physical-stop session cancellation (`G3X_AUTOCONT_REASON_PHYS_STOP`, `g3x_autocont_cancel_latched = 1`)**:
     - When physical `KEY_VIDEO` cancels an active clip or a pending/outstanding restart, `g3x_autocont_cancel_latched = 1` blocks any re-latching of `g3x_autocont_idle_start_press_seen` (`movie_rec.c:1104,1112`) and blocks arming (`movie_rec.c:1151`) while the clip stops or while the user continues holding `KEY_VIDEO` at `IDLE (0)`.
     - `g3x_autocont_cancel_latched` clears to `0` (`movie_rec.c:1121-1124`) **only** when `cur_state == G3X_MOVIE_STATE_IDLE (0)` **and** physical `KEY_VIDEO` is released (`!phys_video_pressed`).
   - **Programmatic live-session cancellation (`PORT-61` `g3x_movie_autocont_cancel_session()`, `g3x_autocont_session_cancelled = 1`)**:
     - Remains available in the shared controller (`G3X_MOVIE_SESSION_CANCEL=1`, `movie_rec.c:820-919`): cancels live sessions (`state in 1..6`) without issuing a stop command (leaving an active clip `mr_rec_state == 1` recording uninterrupted with `LIM:OFF`), preserves `restart_budget`, `restarts_remaining`, and `session_restarts_used`, releases only continuation-owned synthetic keys, yields to physical-stop precedence, is idempotent on repeated calls and a strict no-op when `state == G3X_AUTOCONT_DISARMED`, and clears during runtime **only** on a deliberate physical start after confirmed idle (`movie_rec.c:1104-1109,1149-1170`).
   - **Standalone rearming on the next deliberate physical start after confirmed idle**:
     - Under `G3X_MOVIE_STANDALONE=1`, runtime disarm paths (`g3x_autocont_disarm_with_reason()` in `movie_rec.c:323-353`, including `PHYS_STOP`, budget exhaustion `NONE`, `SESSION_CANCEL`, `PLAYBACK`, `INVALID_STATE`, `STOP_FAULT`, and `TIMEOUT`) terminate the current session immediately to `G3X_AUTOCONT_DISARMED (0)` while preserving `g3x_autocont_enabled = 1` (and setting `g3x_autocont_prev_rec_state = -1` on playback/invalid-state/non-recording disarms so two consecutive polls at `cur_state == G3X_MOVIE_STATE_IDLE (0)` in record mode are required to confirm idle, while `in_playback || invalid_rec_state` at `movie_rec.c:992-1000` avoids overwriting `g3x_autocont_disarm_reason` on repeated polls).
     - Explicit programmatic disable `g3x_movie_autocont_set_enabled(0)` (`movie_rec.c:546-565`) still sets `g3x_autocont_enabled = 0` (`G3X_AUTOCONT_REASON_USER_OFF`) until re-enabled at confirmed idle (`g3x_movie_autocont_set_enabled(1)` or `g3x_movie_autocont_reset()`).
     - Once the camera is in record mode (`camera_info.state.mode_play == 0`) at confirmed `IDLE (0)` (`cur_state == 0 && prev_state == 0 && !g3x_autocont_cancel_latched`), a new deliberate physical `KEY_VIDEO` press observed in `IDLE (0)` followed by `0 -> 1` within `200` polls (`movie_rec.c:1101-1170`) clears any prior disarm reason / `g3x_autocont_session_cancelled` latch, enters `G3X_AUTOCONT_RECORDING (1)`, and initializes a fresh finite budget (`g3x_autocont_restarts_remaining = g3x_autocont_restart_budget = 1U`, `g3x_autocont_session_restarts_used = 0U`).
