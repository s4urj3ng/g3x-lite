## 2. Safe Session Attribution Analysis & Verification (`NO BLOCKER`)

Safe session attribution requires distinguishing a **deliberate physical recording start** (which begins a new user session and initializes the session's restart budget) from a **synthetic continuation recording start** (which continues an existing session after an automatic Reason 3 or Reason 4 stop and must **not** reset or replenish the session's restart budget).

Existing tracked interfaces in `chdk-port/platform/g3x/sub/110c/movie_rec.c` (`full_build/g3x/sub/110c/movie_rec.c`) and `full_build/g3x/kbd.c` support safe session attribution without ambiguity and without any new ROM reads:

1. **Hardware Input Separation (`kbd_new_state[0]` vs. `kbd_mod_state[0]` / `physw_status[0]`)**:
   - On every `10 ms` tick of `mykbd_task()` (`full_build/g3x/kbd.c:174-194`), `my_kbd_read_keys()` (`kbd.c:116-143`) first executes `kbd_update_key_state()`, which calls `kbd_fetch_data(kbd_new_state)` (`kbd.c:145-149`) to read raw physical keys via `_GetKbdState` (`0xFC08EF67`) and `_kbd_read_keys_r2` (`0xFC08EE0D`) into `kbd_new_state[0..2]`.
   - Synthetic `KEY_VIDEO` (`0x00000008`) assertion in `g3x_autocont_assert_synth_press()` (`chdk-port/platform/g3x/sub/110c/movie_rec.c:284-289`) modifies **only** `kbd_mod_state[0]` (via `kbd_key_press(KEY_VIDEO)`) and `physw_status[0]` (`0x00040DAC`). It never writes to `kbd_new_state[0]`.
   - Consequently, `phys_video_pressed` (`((unsigned int)kbd_new_state[0] & G3X_KEY_VIDEO_BIT) == 0U`, `movie_rec.c:692`) reflects strictly physical button presses and is never triggered by continuation-owned synthetic pulses.
2. **Disjoint State-Machine Entry Paths for Physical Session Start vs. Synthetic Continuation Start**:
   - **Physical session start (`G3X_AUTOCONT_DISARMED -> G3X_AUTOCONT_RECORDING`, `chdk-port/platform/g3x/sub/110c/movie_rec.c:765-822`)**:
     - Can occur **only** when `g3x_autocont_state == G3X_AUTOCONT_DISARMED (0)` (`movie_rec.c:765`) and `g3x_autocont_enabled != 0` (`movie_rec.c:743`).
     - Requires `g3x_autocont_idle_start_press_seen == 1`, which is latched at `movie_rec.c:771-777` **only** when `phys_video_pressed == 1` is observed while `cur_state == G3X_MOVIE_STATE_IDLE (0)` and `!g3x_autocont_cancel_latched` (while `g3x_autocont_synth_owned == 0` is enforced at `movie_rec.c:767`).
     - Transitions to `G3X_AUTOCONT_RECORDING (1)` at `movie_rec.c:809-822` when `prev_state == G3X_MOVIE_STATE_IDLE (0) && cur_state == G3X_MOVIE_STATE_RECORDING (1)` within `G3X_AUTOCONT_CONFIRM_POLLS = 200` (`2.0 s`).
   - **Synthetic continuation start (`G3X_AUTOCONT_RELEASING / G3X_AUTOCONT_WAIT_CONFIRM -> G3X_AUTOCONT_RECORDING`, `chdk-port/platform/g3x/sub/110c/movie_rec.c:426-435,1005-1008,1025-1028`)**:
     - Can occur **only** when `g3x_autocont_state` is `G3X_AUTOCONT_RELEASING (5)` (`movie_rec.c:1005-1008`) or `G3X_AUTOCONT_WAIT_CONFIRM (6)` (`movie_rec.c:1025-1028`) following an admitted automatic stop (`RECORDING -> WAIT_IDLE/SETTLE -> PRESSING -> RELEASING`).
     - Calls `g3x_autocont_enter_confirmed_recording()` (`movie_rec.c:426-435`), which transitions directly to `G3X_AUTOCONT_RECORDING (1)` without passing through `G3X_AUTOCONT_DISARMED (0)` and without executing `movie_rec.c:809-822`.
   - **Physical button interaction during pending restart**:
     - If the user physically presses `KEY_VIDEO` during `WAIT_IDLE`, `SETTLE`, `PRESSING`, `RELEASING`, or `WAIT_CONFIRM` (`movie_rec.c:902-906,932-936,959-963,987-991,1020-1024`), physical-stop precedence immediately aborts the restart, releases owned synthetic input, latches `g3x_autocont_cancel_latched = 1` with `G3X_AUTOCONT_REASON_PHYS_STOP`, and disarms to `G3X_AUTOCONT_DISARMED (0)`. Thus a physical press during a pending synthetic restart always terminates the session rather than being misattributed as a new start.

## 3. Smallest Adaptation Reusing Existing Interfaces for Session Restart Budget

### 3.1 Separation of Per-Session Budget State from Per-Clip Metric Reset

In `chdk-port/platform/g3x/sub/110c/movie_rec.c` (`full_build/g3x/sub/110c/movie_rec.c`), `g3x_autocont_reset_session_metrics()` (`movie_rec.c:304-312`) is invoked at three sites:
1. `g3x_autocont_disarm_with_reason()` (`movie_rec.c:317`) and `g3x_movie_autocont_set_enabled()` (`movie_rec.c:500,523`) / `g3x_movie_autocont_reset()` (`movie_rec.c:440`),
2. Initial physical session start arming in `G3X_AUTOCONT_DISARMED` (`movie_rec.c:814`), and
3. Synthetic continuation confirmation in `g3x_autocont_enter_confirmed_recording()` (`movie_rec.c:429`).

Because `g3x_autocont_enter_confirmed_recording()` (`movie_rec.c:429`) calls `g3x_autocont_reset_session_metrics()` on every continued clip, **session budget allowance must not be reset in `g3x_autocont_reset_session_metrics()` or `g3x_autocont_enter_confirmed_recording()`**.

Instead, the smallest adaptation adds volatile session-budget state alongside `g3x_autocont_enabled` (`movie_rec.c:243-260`):
- **Configured volatile restart budget** (e.g., `g3x_autocont_restart_budget`, default `0` = disabled at boot when `g3x_autocont_enabled == 0`, or bounded finite allowance `1..N` when enabled at confirmed idle via `video_submenu_items[]` / `g3x_movie_autocont_menu_change()`).
- **Remaining session restart allowance** (e.g., `g3x_autocont_restarts_remaining`, or session attempts consumed `g3x_autocont_session_restarts_used`):
  - **Initialized / armed**:
    1. When continuation is enabled or budget is adjusted at confirmed idle (`g3x_movie_autocont_can_enable() == 1` in `g3x_movie_autocont_set_enabled()` / budget setter at `movie_rec.c:522-533`), and
    2. When a new physical session arms at `G3X_AUTOCONT_DISARMED -> G3X_AUTOCONT_RECORDING` (`chdk-port/platform/g3x/sub/110c/movie_rec.c:814-822`, `full_build/g3x/sub/110c/movie_rec.c:820-828`), setting `g3x_autocont_restarts_remaining = g3x_autocont_restart_budget` (or `g3x_autocont_session_restarts_used = 0`).
  - **Preserved across synthetic starts**:
    - `g3x_autocont_enter_confirmed_recording()` (`chdk-port/platform/g3x/sub/110c/movie_rec.c:426-435`, `full_build/g3x/sub/110c/movie_rec.c:432-441`) leaves `g3x_autocont_restarts_remaining` (and `g3x_autocont_session_restarts_used`) unchanged when transitioning `RELEASING / WAIT_CONFIRM -> RECORDING`.
  - **Cleared on terminal session exit / reset**:
    - `g3x_autocont_disarm_with_reason()` (`movie_rec.c:314-332`), `g3x_movie_autocont_set_enabled(0)` (`movie_rec.c:492-508`), and `g3x_movie_autocont_reset()` (`movie_rec.c:437-456`) clear active session allowance (`g3x_autocont_restarts_remaining = 0`).

### 3.2 Proposed Admission Point: Consuming Allowance Before Any Synthetic Attempt

In the existing `PORT-59` controller, `g3x_autocont_restart_count` (`chdk-port/platform/g3x/sub/110c/movie_rec.c:259,433`) increments inside `g3x_autocont_enter_confirmed_recording()` **after** the synthetic `KEY_VIDEO` pulse has already been emitted and `mr_rec_state == 1` is confirmed. To enforce a strict pre-attempt restart budget while keeping `g3x_autocont_restart_count` intact as the post-confirmation diagnostic counter:

1. **Stage 1 — Stop-Onset Budget Admission Check (`chdk-port/platform/g3x/sub/110c/movie_rec.c:878-896`, `full_build/g3x/sub/110c/movie_rec.c:884-902` in `case G3X_AUTOCONT_RECORDING:`)**:
   - When `cur_state != G3X_MOVIE_STATE_RECORDING (1)` and physical cancel did not occur:
     1. Evaluate `int eligible = g3x_autocont_check_eligible_stop(&attributed_reason);` (`movie_rec.c:878`) and `g3x_autocont_snapshot_stop_counters();` (`movie_rec.c:879`).
     2. If `!eligible`, disarm as today with `g3x_autocont_disarm_with_reason(0, G3X_AUTOCONT_REASON_STOP_FAULT, 1);` (`movie_rec.c:880-884`).
     3. **Budget admission check (`movie_rec.c:885`)**: Check whether `g3x_autocont_restarts_remaining > 0U` (or `session_restarts_used < session_restart_budget`).
        - If allowance is already `0` (budget exhausted on the previous continuation), **do not enter `G3X_AUTOCONT_WAIT_IDLE` or `G3X_AUTOCONT_SETTLE`**; disarm immediately to `G3X_AUTOCONT_DISARMED` (recording `g3x_autocont_last_stop_reason = attributed_reason`).
2. **Stage 2 — Pre-Attempt Allowance Consumption Before Synthetic Key Assertion (`chdk-port/platform/g3x/sub/110c/movie_rec.c:885,950-953`, `full_build/g3x/sub/110c/movie_rec.c:891,956-959`)**:
   - Consume 1 unit of restart allowance (`g3x_autocont_restarts_remaining--`) **before** `g3x_autocont_assert_synth_press()` is called:
     - Either upon stop-onset admission at `movie_rec.c:885` (when admitting `G3X_AUTOCONT_RECORDING -> G3X_AUTOCONT_WAIT_IDLE / G3X_AUTOCONT_SETTLE`, paired with a defensive `if (g3x_autocont_restarts_remaining == 0)` / pre-consumed token check at `movie_rec.c:950`), **or** at the `G3X_AUTOCONT_SETTLE -> G3X_AUTOCONT_PRESSING` transition (`movie_rec.c:950-953`) immediately before `g3x_autocont_state = G3X_AUTOCONT_PRESSING; g3x_autocont_assert_synth_press();` (after checking `g3x_autocont_restarts_remaining > 0U` at `movie_rec.c:885`).
   - In both placements:
     - When `restarts_remaining == 0` at the end of the final allowed clip, the controller disarms immediately at `1 -> != 1` (`movie_rec.c:885`) without entering `WAIT_IDLE` or `SETTLE`.
     - Allowance is consumed **before** `g3x_autocont_assert_synth_press()` (`movie_rec.c:952`) emits any synthetic `KEY_VIDEO` press, so a failed or timed-out synthetic attempt in `PRESSING` / `RELEASING` / `WAIT_CONFIRM` cannot retain unconsumed allowance or retry.
     - When the synthetic attempt succeeds and enters `g3x_autocont_enter_confirmed_recording()` (`movie_rec.c:426-435`), the remaining budget is **not** reset, so a session configured with budget `B` performs at most `B` synthetic restart attempts across `B + 1` total clips.
