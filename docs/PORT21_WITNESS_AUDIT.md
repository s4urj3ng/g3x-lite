# PORT-21 Witness Audit: Writer vs Inspector Roundtrip Verification (Hypothesis H4)

## 1. Executive Summary & Evaluation of Hypothesis H4

### 1.1 Objective & Context
During the physical camera execution trial for CHDK-PORT-2A (PowerShot G3 X GM1.10C), observation **O6** was recorded: the Canon Basic Witness Inspector reported `WITNESS_INVALID` on Line 1 (`h_title`) and `INVALID / CORRUPT` on Line 2 (`h_status`), returning sentinel `0x574954EE` (`docs/PORT18_OWNER_TRIAL_PLAN.md:267, 288`).

Hypothesis **H4** posits:
> *"The LOADER witness record at 0x0035F7A0 was malformed, given the code exactly as built."*

This audit conducts a host-based, field-by-field verification comparing the witness writer routines in the loader (`chdk-port/loader/g3x/main_prototype.c:40-56`) and core (`chdk-port/platform/g3x/sub/110c/boot_prototype.c:26-56`) against the witness inspector parser executed by the owner (`firmware/tools/witness_inspector_gm110c.m`, `firmware/tools/witness_inspector_payload.S`, and host reference `tools/validate_witness_inspector.py`).

### 1.2 Verdict on Hypothesis H4: REFUTED (`[VERIFIED]`)
- **Hypothesis H4 is REFUTED**: The loader witness record generated by the code exactly as built in `candidate_port2a/candidate_loader.elf` is **NOT malformed** `[VERIFIED]`.
- When the record bytes written by the loader (Stage 1 only: `magic=0x5749544E`, `version=0x00010001`, `session_nonce=0x32A80001`, `stage_state=0x01`, `loader_sp=0x00007FF8`, `core_entry_pc=0`, `cont_tick=0`, `checksum=0x3028882D`) are parsed by the real inspector code (`emulate_inspector_parse`), the inspector reports:
  - Title: `LOADER_REACHED`
  - Status: `FRESHNESS_UNVERIFIED`
  - Colors: Title Color 1 (White), Status Color 4 (Yellow)
  - Return Sentinel: `0x57495401` (`SENTINEL_LOADER`)
  - **Verdict: VALID** `[VERIFIED]`.
- The loader-only record is **never** reported as `WITNESS_INVALID` / `INVALID / CORRUPT` `[VERIFIED]`.
- Therefore, the on-camera observation O6 (`WITNESS_INVALID` / `INVALID / CORRUPT`, Sentinel `0x574954EE`) **cannot** have been caused by a malformed record emitted by the loader. Instead, O6 demonstrates that memory at `0x0035F7A0` contained uninitialized RAM (all-zeros) or stock-boot data when the inspector executed, indicating that the loader witness write routine either never ran or was subsequently overwritten `[VERIFIED]`.

### 3.1 Checksum Algorithm and Coverage Verification
- **Formula**:
  $$\text{checksum} = c_7, \quad \text{where } c_0 = \text{0x55AA55AA}, \quad c_{k+1} = (c_k \times 31) \oplus w_k \quad (k \in 0..6)$$
- **Coverage**: Exactly the 7 32-bit words: `magic`, `version`, `session_nonce`, `stage_state`, `loader_sp`, `core_entry_pc`, and `cont_tick` `[VERIFIED]`.
- **Loader Compilation**: In `candidate_port2a/candidate_loader.elf`, GCC optimizes `c_0 * 31` to literal `0x5FA05F96`, evaluating `(((0x5FA05F96 ^ magic) * 31) ^ version) * 31 ... ^ cont_tick`. Disassembly of `candidate_loader.elf:8008-8040` matches the loop in `firmware/tools/witness_inspector_payload.S:75-87` bit-for-bit `[VERIFIED]`.
- For the loader-only record with `loader_sp = 0x00007FF8`, the exact checksum is **`0x3028882D`** `[VERIFIED]`.

## 4. Failure Mapping to `WITNESS_INVALID` / `INVALID / CORRUPT`

In `firmware/tools/witness_inspector_payload.S:190-198` and `tools/validate_witness_inspector.py:244-273`, any structural violation routes unconditionally to the failure terminal `.Lstate_invalid`:

```text
.Lstate_invalid:
    Title String:     "WITNESS_INVALID"
    Status String:    "INVALID / CORRUPT"
    Title Color:      3
    Status Color:     3
    Return Sentinel:  0x574954EE (SENTINEL_INVALID)
```

The inspector maps each of the following distinct memory states to this identical output:
1. **Truncated Buffer**: Memory buffer under 32 bytes (`len(buf) < 32`) `[VERIFIED]`.
2. **Corrupted Magic**: `magic != 0x5749544E` (e.g. all-zeros `0x00000000`, stock pointers, uninitialized RAM) `[VERIFIED]`.
3. **Unsupported Version**: `version != 0x00010001` `[VERIFIED]`.
4. **Checksum Mismatch**: Any single bit flip or modification in any field without recalculating `checksum` `[VERIFIED]`.
5. **Illegal Stage Mask**: `stage_state` not in `{1, 3, 7}` (e.g. `0x00` empty, `0x02` core-only, `0x04` continuation-only, `0x05` core-skipped) `[VERIFIED]`.
6. **Continuation Core Entry Mismatch**: At Stage 3 (`stage_state == 7`), `core_entry_pc != 0x003489B5` `[VERIFIED]`.
7. **Continuation Stack Misalignment**: At Stage 3 (`stage_state == 7`), `loader_sp % 8 != 0` `[VERIFIED]`.

### 5.1 Implications for the Trial Execution
Because a properly written loader record is reported as `LOADER_REACHED` (`0x57495401`), the O6 reading proves:
1. **The loader witness record was never present in DRAM at `0x0035F7A0` when the inspector executed.**
2. Either DISKBOOT.BIN was not booted by the Canon bootloader, or execution halted before reaching `main_prototype.c:42`, or the DRAM controller was re-initialized / cleared by a warm restart before the inspector script executed `[INFERRED]`.

## 6. Display Color Analysis: Colour Index 3 and Light Blue

### 6.1 Documentation Misconception vs Hardware Reality
- **Developer Documentation & Comments**:
  In `firmware/tools/witness_inspector_gm110c.m:7, 12, 16`, `firmware/tools/witness_inspector_payload.S:193-194`, and `docs/PORT18_OWNER_TRIAL_PLAN.md:220, 267`, Color Index 3 is described as **"Red"**:
  > `movs r6, #3 /* Color 3 = Red */`
  > `WITNESS_INVALID / INVALID / CORRUPT (Red/Red)`
- **Hardware Palette Architecture (GM1.10C ROM)**:
  1. The native payload calls `LCDMsg_ChangeColor_native` (`0xFC0C99B0`) with `r1 = 3` `[VERIFIED: payload.S:216-232]`.
  2. `LCDMsg_ChangeColor_native` stores `r1` into descriptor offset `+0x08` `[VERIFIED: PRIMARY.BIN 0xFC0C99C2]`.
  3. When rendering, `0xFC0C959E` reads `desc->color` and passes it to lookup subroutine `0xFC33D118` `[VERIFIED]`.
  4. `0xFC33D118` indexes a `uint16_t` lookup table at `0xFC77E0DC` (loaded via struct base `0x00015DA4 + 0x1C`) `[VERIFIED]`:
     - `table[0] = 36` (`0x0024`) $\implies$ Palette 0 entry 36 = `0xFFD5C00E` (Yellow / Gold)
     - `table[1] = 1` (`0x0001`) $\implies$ Palette 0 entry 1 = `0xFFFFFFFF` (White)
     - `table[2] = 35` (`0x0023`) $\implies$ Palette 0 entry 35 = `0xFF0DB671` (Green)
     - **`table[3] = 37` (`0x0025`)** $\implies$ **Palette 0 entry 37 = `0xFF2D94FF` (Light Blue)**
     - `table[4] = 3` (`0x0003`) $\implies$ Palette 0 entry 3 = `0xFFEFEFEF` (Light Gray)
  5. In ROM Default Palette 0 (`0xFC77C8B0`), Entry 37 at `0xFC77C944` holds `0xFF2D94FF`:
     - `Alpha = 0xFF` (Opaque, from bits 25:24)
     - `Red = 0x2D` (45)
     - `Green = 0x94` (148)
     - `Blue = 0xFF` (255)
     - **RGB(45, 148, 255) is Light Blue / Sky Blue, NOT Red!** `[VERIFIED]`.

### 6.2 Significance for the Inspector's Display
- **Logical / Control Flow**: **No effect** `[VERIFIED]`. The inspector's branch decisions, string generation (`"WITNESS_INVALID"`, `"INVALID / CORRUPT"`), memory checks, and return sentinel (`0x574954EE`) are completely independent of the visual color rendering.
- **Visual On-Screen Appearance**: On the physical camera LCD, when `.Lstate_invalid` is triggered, the text lines are rendered in **Light Blue**, NOT **Red** `[VERIFIED]`.
- **Trial Observation Correlation**: If the owner observed text displayed in **Light Blue** during trial execution, this directly confirms that the native payload selected **Color Index 3** (the `.Lstate_invalid` error state) `[INFERRED]`. The expectation of "(Red/Red)" in the trial documentation was a historical labeling error inherited from other Canon models.

## 7. Host Test Suite Summary (`tests/test_port21_witness_roundtrip.py`)

A comprehensive unit test suite has been implemented in `tests/test_port21_witness_roundtrip.py`:
- `test_loader_only_record_is_valid`: Constructs exact loader-only record and asserts inspector reports `LOADER_REACHED` / `FRESHNESS_UNVERIFIED` (Sentinel `0x57495401`, Colors `1, 4`).
- `test_c_struct_packing_and_loader_disassembly_coherence`: Compiles `boot_witness.h` with host C compiler, proving 32-byte struct size and exact checksum `0x3028882D`.
- `test_all_zero_region_yields_witness_invalid`: Confirms 32 bytes of zeros yields `WITNESS_INVALID` / `INVALID / CORRUPT` (Sentinel `0x574954EE`, Colors `3, 3`).
- `test_overwritten_stock_boot_data_yields_witness_invalid`: Evaluates 5 patterns of stock-boot and uninitialized memory, proving all yield `WITNESS_INVALID`.
- `test_valid_records_across_all_stages`: Tests Stage 1, Stage 2, and Stage 3 valid records.
- `test_exhaustive_rejection_modes_mapping_to_witness_invalid`: Exhaustively tests short buffer, invalid magic, invalid version, bit flips, illegal stage progressions, invalid core entry PC, and misaligned loader stack.
- `test_colour_index_3_palette_mapping_analysis`: Verifies the RGB components of Palette 0 Entry 37 prove Light Blue coloring.

All tests execute offline and pass cleanly without requiring ROM reads or camera hardware.
Candidate builder (`candidate_build`) and candidate validator (`candidate_validate`) remain invariant and passing.
