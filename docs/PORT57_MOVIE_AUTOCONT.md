# PORT-57 — Movie Auto-Continuation Stop Attribution & Keyboard Restart Evidence

**Verdict**: **IMPLEMENTATION SUPPORTED** (non-invasive polling and synthetic `KEY_VIDEO` restart from `my_kbd_read_keys()` without `FULL_HOOKS` or `task_MovieRecord` replacement). Physical camera behavior remains **UNVERIFIED** (Phase 0 / hardware **STRICT NO-GO** until owner trial).

- **Stop Attribution**: Bounded ROM inspection of `0xFC098B00..0xFC098DFF` (`length = 0x300` / `768` B, SHA-256 `32bec616fbcefa305b66102cab9e09c380bb14f7870b878d9fdd0e386c584d4f`, recorded in `docs/port34_evidence_manifest.json` as `PORT57-ROM-CHECK-LIMITS-WINDOW`) verifies the 32-bit width (`str.w` / `str`) and exact RAM predicate operands for both Reason 4 (duration/frame limit at `0xFC098B28`) and Reason 3 (4 GiB file size cap at `0xFC098C5C`, distinct from Reason 2 storage-full at `0xFC098C3A..3C`). Because clearing/reset of `*(uint32_t *)0x0000C0C0` on recording start or user stop lies outside the authorized ROM window and remains `UNKNOWN`, attributing Reason 3 or 4 to the **current stop** combines `*(volatile const uint32_t *)0x0000C0C0 == 3` or `4` at the `RECORDING (1) -> STOPPING/IDLE (!= 1)` transition with per-session in-bounds active-recording observation, the `ROM_VERIFIED` limit-threshold failure predicate in RAM (`0x0000C278`/`0x0000C274` for Reason 4; `0x0000C2A0`/`0x0000C2A8`/`0x0000C0D8`/`0x0000C290`/`0x0000C078` for Reason 3), and a raw physical button veto (`kbd_new_state[0]` before synthetic overrides). Zero writes to `0x0000C0C0` are performed.
- **Restart Trigger**: Keyboard simulation of `KEY_VIDEO` (`word 0, bit 3 = 0x00000008`, active-low) is preferred. Because CHDK core `kbd_update_key_state()` (`chdk-port/core/kbd_common.c:166-184`) only merges `kbd_mod_state[0]` into `physw_status[0]` (`0x00040DAC`) when `kbd_process() != 0` (i.e. inside `<ALT>` mode) and `kbd_key_release_all()` (`kbd_process.c:174`, `script.c:269,288`) clobbers `kbd_mod_state[0]`, the auto-continue state machine in `my_kbd_read_keys()` must own a bounded press/release countdown after `mr_rec_state` returns to `IDLE (0)`: asserting both `kbd_key_press(KEY_VIDEO)` and `physw_status[0] &= ~0x00000008` for the press window (`6` polls = `60 ms`), then explicitly calling `kbd_key_release(KEY_VIDEO)` and releasing bit 3 in `physw_status[0]` for a cooldown window (`>= 6` polls = `60 ms`).
