## Notes

1. **Base branch & G3X_CONF_SAVE isolation**: This milestone sits on the PORT-54 integration branch (`0593f5b`), but does not use or require `G3X_CONF_SAVE`. Movie status investigation is entirely independent of filesystem write permissions or configuration persistence.
2. **Missing FINSIG stubs**: `reference/finsig_gm110c/stubs_entry.S` defines `task_MovieRecord` (`0xFC09AC19`), but defines neither `simple_movie_status` nor `movie_status`. On DIGIC 6 siblings (G7X, G5X, SX280HS), `simple_movie_status` is defined manually in `stubs_min.S` rather than emitted by `finsig`.
3. **ROM audit of historical stub `0x0000C170`**: Historical G3X `stubs_min.S:7` defined `DEF(simple_movie_status, 0x0000C170)` with the comment `// Found @0xFC09BD60 via task_MovieRecord (0x0000C078 + 0x80 + 0x78)`. Bounded ROM inspection of `0xFC09BD30..0xFC09BD80` (80 B, SHA-256 `66128d3d...`) reveals that `0xFC09BD60` is inside the Command 12 teardown handler (`MovieRecorder_BufferRelease`), which loads `0x0000C078`, adds `0x80` (`0x0000C0F8`), adds another `0x80` (`0x0000C178`), and stores 1 to `[r1, #0x78]` (`0x0000C1F0`). The comment omitted the second `0x80` addition (`0xC078 + 0x80 + 0x78 = 0xC170`). Furthermore, this is a teardown handler rather than active recording status.
4. **Verified recording state variable `0x0000C0C8`**: Bounded ROM inspection of `0xFC09B416..0xFC09B436` (32 B, SHA-256 `98059580...`) confirms that `MovieRecorder_GetElapsedSeconds` directly queries `mr_rec_state` at `0x0000C0C8` (`*(0x0000C078 + 0x50)`), comparing it with `#1`. When `*(0x0000C0C8) == 1`, recording is active; when `*(0x0000C0C8) == 0`, camera is idle. If `stubs_min.S:7` is updated to `0x0000C0C8`, `is_video_recording()` evaluates correctly. If hardware trial leaves this unconfirmed, fallback to `MOV:?` applies.
5. **Diag line integration**: The secondary ALT diagnostic line in `chdk-port/platform/g3x/gui_diag.h` (`g3x_diag_format_line2:1066`, `gui_diag_draw:1414`, `g3x_playback_menu_diag_format:1543`) has sufficient margin within the 55-character line limit (`G3X_DIAG_LINE_MAX_CHARS`) to display `MOV:IDLE`, `MOV:REC`, or `MOV:?`.
6. **Roadmap item 3b planning**: Sibling movie time limit handling (SX280HS `set_movie_time_limit`, `conf.ext_video_time`) is documented in rows 5a–5e for planning purposes only. Zero implementation changes were made for movie time limits.
