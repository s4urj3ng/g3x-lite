### 2.2 Continuation States, Function/Constant Names & Reason Metadata (`movie_rec.c`)

In `chdk-port/platform/g3x/movie_status.h:169-256` and `chdk-port/platform/g3x/sub/110c/movie_rec.c:216-1058`, a single state machine (`g3x_autocont_state`) polled every `10 ms` inside `mykbd_task` drives all continuation behavior and UI status projection:

- **Timing / poll constants (`movie_rec.c:228-233`)**:
  - `G3X_AUTOCONT_MAX_STOP_POLLS = 500` (`5.0 s` max wait in `G3X_AUTOCONT_WAIT_IDLE` for `mr_rec_state` in `2..4` to reach `0`)
  - `G3X_AUTOCONT_SETTLE_POLLS = 50` (`500 ms` continuous `mr_rec_state == 0` settle in `G3X_AUTOCONT_SETTLE`)
  - `G3X_AUTOCONT_PRESS_POLLS = 6` (`60 ms` synthetic `KEY_VIDEO` press pulse in `G3X_AUTOCONT_PRESSING`)
  - `G3X_AUTOCONT_RELEASE_POLLS = 6` (`60 ms` post-pulse release window in `G3X_AUTOCONT_RELEASING`)
  - `G3X_AUTOCONT_CONFIRM_POLLS = 200` (`2.0 s` max wait for `mr_rec_state == 1` in `G3X_AUTOCONT_WAIT_CONFIRM`)
  - `G3X_AUTOCONT_START_HOLD_POLLS = 50` (`500 ms` max carry-over of the initial physical `KEY_VIDEO` start press into `G3X_AUTOCONT_RECORDING`)
- **Explicit disarm / fault reason enum (`g3x_movie_autocont_reason_t`, `movie_status.h:202-211`)**:
  - `G3X_AUTOCONT_REASON_NONE = 0` (`"NONE"`) — Initial boot state or currently enabled/active with no disarm/fault event.
  - `G3X_AUTOCONT_REASON_USER_OFF = 1` (`"USER"`) — User explicitly disabled the menu toggle (`g3x_movie_autocont_set_enabled(0)`). Displays `"OFF"` / `"Off"` (never faulted).
  - `G3X_AUTOCONT_REASON_PHYS_STOP = 2` (`"STOP"`) — Terminal physical `KEY_VIDEO` stop/cancellation during an active session; latches `g3x_autocont_cancel_latched = 1`, disarms the active session to `G3X_AUTOCONT_DISARMED`, and keeps `g3x_autocont_enabled = 1` (`"RDY"` / `"Ready"`) in record mode so physical stop remains terminal for the current session until confirmed idle + key release + a new deliberate physical start.
  - `G3X_AUTOCONT_REASON_PLAYBACK = 3` (`"PLAY"`) — Camera entered playback mode (`camera_info.state.mode_play != 0`) while continuation was enabled or active. Fault/disarmed (`g3x_movie_autocont_is_faulted() == 1`).
  - `G3X_AUTOCONT_REASON_INVALID_STATE = 4` (`"STATE"`) — Invalid/out-of-range `mr_rec_state` (`< 0` or `> 4`) or unexpected non-idle state bounce during `WAIT_IDLE`, `SETTLE`, `PRESSING`, `RELEASING`, or `WAIT_CONFIRM`. Fault/disarmed (`g3x_movie_autocont_is_faulted() == 1`).
  - `G3X_AUTOCONT_REASON_STOP_FAULT = 5` (`"LIMIT"`) — Recording left `mr_rec_state == 1` with an ineligible, unattributable, stale, or card-full stop reason in `g3x_autocont_check_eligible_stop()`. Fault/disarmed (`g3x_movie_autocont_is_faulted() == 1`).
  - `G3X_AUTOCONT_REASON_TIMEOUT = 6` (`"TMO"`) — `WAIT_IDLE` (`G3X_AUTOCONT_MAX_STOP_POLLS = 500`) or `WAIT_CONFIRM` (`G3X_AUTOCONT_CONFIRM_POLLS = 200`) timer expired without reaching target state. Fault/disarmed (`g3x_movie_autocont_is_faulted() == 1`).

### 2.3 Volatile Menu Toggle Rules & Non-Overwriting Poll Semantics

1. **Starts Disabled Every Boot & Never Persists**:
   - `g3x_autocont_enabled` initializes to `0` (`G3X_AUTOCONT_DISARMED`, `G3X_AUTOCONT_REASON_NONE`) at boot and on `g3x_movie_autocont_reset()`. It is never stored in `struct Conf`, `conf_info[]`, or `A/CHDK/CCHDK4.CFG`.
2. **Confirmed-Idle Enable Gating (`g3x_movie_autocont_can_enable()`, `movie_rec.c:459-481`)**:
   - Returns `1` if and only if:
     1. `camera_info.state.mode_play == 0` (camera is in record/live-view mode, not playback),
     2. `g3x_get_movie_status() == G3X_MOVIE_STATE_IDLE` (`mr_rec_state == 0` at `0x0000C0C8`),
     3. `g3x_autocont_saw_boot_idle != 0` (at least one poll has confirmed `mr_rec_state == 0` during this boot), and
     4. `((unsigned int)kbd_new_state[0] & G3X_KEY_VIDEO_BIT) != 0U` (raw physical `KEY_VIDEO` is currently released).
   - Calling `g3x_movie_autocont_set_enabled(1)` when `g3x_movie_autocont_can_enable() == 0` is **refused** (returns `0`, leaves `g3x_autocont_enabled = 0`, does not overwrite an existing fault/disarm reason, and never emits any key press).
   - Calling `g3x_movie_autocont_set_enabled(1)` when `g3x_movie_autocont_can_enable() == 1` sets `g3x_autocont_enabled = 1`, clears `g3x_autocont_disarm_reason = G3X_AUTOCONT_REASON_NONE`, clears `g3x_autocont_cancel_latched = 0`, resets `g3x_autocont_idle_start_press_seen = 0`, sets `g3x_autocont_prev_rec_state = G3X_MOVIE_STATE_IDLE (0)`, and remains in `G3X_AUTOCONT_DISARMED` (`"RDY"` / `"Ready"`, **Enabled but Unarmed**). Enabling never starts recording.
3. **Arming Only on a Subsequent Deliberate Physical Recording Start (`movie_rec.c:775-852`)**:
   - While `g3x_autocont_enabled == 1` in `G3X_AUTOCONT_DISARMED`, `g3x_autocont_idle_start_press_seen` is latched to `1` only when a physical `KEY_VIDEO` press (`phys_video_pressed == 1`) is observed while `cur_state == G3X_MOVIE_STATE_IDLE (0)` and `!g3x_autocont_cancel_latched`.
   - On a `0 -> 1` transition (`prev_state == G3X_MOVIE_STATE_IDLE && cur_state == G3X_MOVIE_STATE_RECORDING`), continuation transitions to `G3X_AUTOCONT_RECORDING` (`"ARM"` / `"Armed"`) **only** if `g3x_autocont_enabled != 0`, `!g3x_autocont_cancel_latched`, and `g3x_autocont_idle_start_press_seen != 0`. A `0 -> 1` state transition without a physical movie-key start press observed at confirmed `IDLE` after enabling cannot arm continuation.
4. **Immediate User Disable Without Stopping an Active Clip (`g3x_movie_autocont_set_enabled(0)`, `movie_rec.c:490-516`)**:
   - Accepted immediately in every state (including active recording `mr_rec_state == 1` or pending restart states `WAIT_IDLE`, `SETTLE`, `PRESSING`, `RELEASING`, `WAIT_CONFIRM`).
   - Releases synthetic `KEY_VIDEO` **only** if continuation-owned (`g3x_autocont_release_synth_input()` checks `if (g3x_autocont_synth_owned)`), cancels pending restart timers, sets `g3x_autocont_state = G3X_AUTOCONT_DISARMED`, `g3x_autocont_enabled = 0`, and `g3x_autocont_disarm_reason = G3X_AUTOCONT_REASON_USER_OFF`.
   - Never presses `KEY_VIDEO` and never writes to `MovieRecorder` RAM, so an active clip continues recording uninterrupted.
5. **Owned-Only Synthetic Key Release Including in `G3X_AUTOCONT_RELEASING` (`movie_rec.c:291-312,983-1017`)**:
   - The unconditional `kbd_key_release(KEY_VIDEO); physw_status[0] |= (long)G3X_KEY_VIDEO_BIT;` previously in `G3X_AUTOCONT_RELEASING` has been removed and replaced with `g3x_autocont_release_synth_input()`, which touches `kbd_mod_state[0]` and `physw_status[0]` strictly when `g3x_autocont_synth_owned != 0`.
6. **Deliberate Reason Preservation Across Repeated Polling (`movie_rec.c:716-773`)**:
   - When `camera_info.state.mode_play != 0` or `cur_state` is invalid (`< 0` or `> 4`), `g3x_movie_autocont_poll()` disarms with `G3X_AUTOCONT_REASON_PLAYBACK` or `G3X_AUTOCONT_REASON_INVALID_STATE` **only** if continuation was enabled (`g3x_autocont_enabled != 0`) or active (`g3x_autocont_state != G3X_AUTOCONT_DISARMED`).
   - Once continuation is disarmed and disabled (`g3x_autocont_enabled == 0 && g3x_autocont_state == G3X_AUTOCONT_DISARMED`), repeated 10 ms polls in playback mode, invalid state, or idle never overwrite `g3x_autocont_disarm_reason` (`USER_OFF`, `PHYS_STOP`, `PLAYBACK`, `INVALID_STATE`, `STOP_FAULT`, or `TIMEOUT`). Thus user disable (`OFF`) and fault/disarm (`FLT`) remain permanently distinguishable until the user next toggles the control.

### 5.2 Candidate Limitations & Remaining `UNKNOWN` / `INFERRED` Runtime Assumptions

1. **`U1` — Runtime Clearing Lifecycle of `mr_stop_reason` (`0x0000C0C0`) (`UNKNOWN` in ROM / `INFERRED` Counter-Movement Guard)**:
   - Stores of `2` (card space full), `3` (4 GiB size cap), and `4` (frame-count cap) to `*(uint32_t *)0x0000C0C0` are `ROM_VERIFIED` inside `0xFC098B00..0xFC098DFF` (`PORT57-ROM-CHECK-LIMITS-WINDOW`), whereas `MovieRecorder_StartRecording` (`0xFC09B080`), Command 1 manual stop (`0xFC09A668`), and `MovieRecorder_FinalizeStop` (`0xFC099DC4`) lie outside the recorded ROM window (`UNKNOWN`). The candidate does not assume firmware zeroes `0x0000C0C0`; it combines `*(0x0000C0C0) == 3` or `4` with per-session counter movement (`cur_frames`, `stream_bytes`, `proj_total`) and threshold cross-checks (`INFERRED`).
2. **`U2` — Post-`IDLE` UI Settle Window (`G3X_AUTOCONT_SETTLE_POLLS = 50` / `500 ms`) (`UNKNOWN` in ROM / `INFERRED` Timing Bound)**:
   - Exact wall-clock completion time of `MovieRecorder_FinalizeStop` (`0xFC099DC4`) and `SsMovieRec_HandleStopAndDigest` (`0xFC070AFA`) after `mr_rec_state` (`0x0000C0C8`) reaches `0` before Canon's UI task accepts a new `KEY_VIDEO` press edge is `UNKNOWN` in ROM and `INFERRED` at `500 ms` (`50` consecutive polls at `mr_rec_state == 0`).
3. **`U3` — Physical Firmware Acceptance of Synthetic `KEY_VIDEO` Pulse (`60 ms` Press / `60 ms` Release) (`INFERRED`)**:
   - Injecting active-low bit 3 (`0x00000008`) into `kbd_mod_state[0]` and `physw_status[0]` (`0x00040DAC`) for `6` polls (`60 ms`) followed by `6` release polls (`60 ms`) inside `my_kbd_read_keys()` before `_kbd_p1_f_cont` (`0xFC128695`) / `_kbd_p2_f` (`0xFC12811F`) is `INFERRED` to start the next clip cleanly in both normal live view and `<ALT>` mode.
4. **`U4` — Inter-Clip Gap (`~1.5–4.0 s`) & Architectural Scope Limitations**:
   - **Discrete `.MP4` segments with inter-clip gap**: Because `G3X_MOVIE_AUTOCONT_UI=1` keeps `MovieRecorder` RAM strictly read-only (`G3X_MOVIE_NOLIMIT` OFF) and waits for stock MP4 container finalization (`mr_rec_state` `2..4 -> 0`, bounded by `5.0 s`) plus the `500 ms` settle delay and `60 ms` synthetic press before starting the next file, automatic continuation produces sequential `.MP4` files (`MVI_xxxx.MP4`, `MVI_xxxx+1.MP4`) separated by an `INFERRED` **~1.5 to 4.0 second** gap.
   - **Volatile-only setting**: Because `G3X_CONF_SAVE` is OFF (`G3X_DISABLE_CARD_WRITES=1`, `OPT_DISABLE_FILE_WRITES=1`), `"Auto-Continue Movie"` is intentionally volatile in RAM and resets to `Off` (`AC:OFF`) on every camera reboot or battery pull.
